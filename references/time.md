# 时间规则

语义时间表示信息在现实中的位置；created_at/updated_at 只表示系统何时存储。所有记录明确声明模式，不因文件有修改日期就把全部资料塞进时间线。

| 情况 | 模式 | 示例 |
|---|---|---|
| 名称、概念说明、未声明阶段的兴趣/价值观/习惯 | none | 对某概念的定义；偏好安静环境 |
| 事件、一次决定 | point | 毕业、出行、选型决定 |
| 任职、居住、关系阶段、有效期、阶段性偏好 | interval | 2022–2024 任职；今年起戒咖啡 |
| 确有时间但不知道 | point/interval，值为 null | 不知道哪年搬过家 |

event、decision、state 不可用 none。profile/preference/routine/goal/project 按内容判断。source 导入日期不等于材料发生日期，默认 none；原文事件单独提取。

```json
{"mode":"none"}
{"mode":"point","at":"2026-10-11"}
{"mode":"point","at":"2026-10-11T20:00:00+08:00"}
{"mode":"point","at":null,"precision_note":"发生过，日期未提供"}
{"mode":"interval","start":"2022-09","end":"2024-06"}
{"mode":"interval","start":"2025","end":null,"precision_note":"结束时间未记录"}
```

- 支持年/月/日及带时区偏移的 ISO 时间戳。按原文精度保存。
- end:null 仅代表结束时间未记录；结合 status 与证据判断是否持续，不能直接推断当前有效。
- active/historical/disputed/retracted 是记录的认知与生命周期状态；none 也可是历史或已撤回。
- 相对日期用用户消息当时的时间/时区转换，正文保留原话；时间背景不明则不根据执行机器日期猜测。
- 没有共同时间范围的事实分成记录，用 about/part_of 关联，不把一个时间字段套给不同时期的事实。

## 变化与纠错

“去年改喝茶了”：旧偏好保留为历史，已知时填写结束范围；新偏好带开始时间并 supersedes 旧记录，不能虚构分界日。

“之前记错了，我不喝咖啡”：旧记录 retracted，新记录引用纠正来源。错误结论不进入默认查询，调查错误历史时可显式读取。

“他说我喜欢咖啡，但我不认同”：分别保存第三方陈述与自述，标注冲突，不以最新写入覆盖。

## 排序与过滤

- timeline 按 point.at 或 interval.start 降序；未知末尾，none 排除。
- 同时刻按 ID 稳定排序，这不代表因果。
- 年/月精度按日历区间起点分桶，仍显示原精度；精度范围重叠时不能断言严格先后。呈现时可单列“2026 年，月份未知”。
- 精确时间按 UTC 比较，保存和显示保留原时区偏移。
- timeline --since/--until 过滤发生点/开始时间，不是区间重叠查询。未知时间不进入有日期过滤的结果，另查并说明。
- “某月仍在任职/进行的项目”：枚举 state/project，比较 start/end 与目标时段交集，不只用开始时间过滤。边界未知则列为可能匹配。
- “当前”：结合状态、语义时间、纠正关系判断。缺少结束证据时说最近已知状态，不擅自补结束日期。
