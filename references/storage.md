# 外部配置与 Git 存储

## 配置发现与保存

默认位置为 `~/.config/personal-atlas/config.json`；`~/.config/personal-atlas` 是配置目录，不存个人资料。也接受当前对话、上层 plugin 说明、项目说明、连接器上下文和用户指定的其他外部位置。上下文配置与本机文件都是有效来源，本机文件不是前置条件；上下文信息足够时直接继续，无需读取或创建本机文件。ChatGPT 可直接采用已加载的上层 plugin 说明中的配置。本机路径不可达、不可访问或不存在时，继续使用上下文，只在必要信息仍缺失时提示补充。同一任务优先采用用户最新明确指定的目标；其余来源若给出不同仓库、分支或凭据身份，先指出冲突并请用户选择。不扫描无关目录寻找令牌，不自动迁移 Skill 内旧配置或跨插件复制凭据。

配置示例（占位值，不是默认绑定）：

```json
{
  "schema_version": 2,
  "provider": "gitlab",
  "remote": "https://git.example.org/USER/ATLAS.git",
  "branch": "chosen-branch",
  "expected_vault_id": null
}
```

- remote 必需，可为现有工具支持的 HTTPS 或 SSH 仓库地址；不得内嵌密码或 token。自建服务保留完整主机与项目路径，不假设只有 owner/repo 两段。
- provider 可为 github、gitlab、gitee 或 self-hosted，也可由明确域名/已连接工具确定。自建域名无法推断实现时依工具元数据或询问用户，不套用 GitHub API。
- branch 可省略，由现有工具读取默认分支；无法查询时提示补充。不把示例分支写成运行默认值。
- expected_vault_id 可选，用于用户希望校验固定资料库身份时；通常从 atlas/vault.json 读取并核对 graph.vault_id，无需用户事先提供。
- credentials 可选。若所选能力支持外部 PAT 配置，可增加 `{"credentials":{"type":"pat","token":"<可选令牌>"}}`；否则使用该工具自身的授权或凭据引用格式。无令牌不算配置不完整，除非实际工具要求且尚无可用授权。

用户要求保存或更新连接配置时，将已提供且明确的字段写到选定的外部位置，保留无关字段。宿主允许本地写入时目录权限 0700、含凭据文件权限 0600；受宿主权限限制则准确提示。没有本机文件访问能力时直接使用当前上下文配置。已有上层 plugin 说明可作为配置来源，不因没有本机副本声称“未配置”或“未持久保存”；仅当用户要求保存本轮新配置且无法写入选定位置时说明尚未完成该写入，并提示可访问的外部配置位置。令牌不得出现在回复、命令行、日志、仓库或 Skill 包中。

## 缺失与故障

区分配置缺失和工具缺失：缺 remote 则索取仓库地址；缺 branch 先查询默认分支；宿主没有目标服务的工具则提示连接或启用适配能力。工具已授权时不重复索取 PAT。读取失败按实际错误报告；404 也可能是权限或地址问题，不能自动创建新库或初始化。

## 初始化与存储结构

目标可为任意用户指定的 Git 仓库，空库、含其他业务文件或含其他 Skill 数据均可；固定使用仓库根目录下的 `atlas/`，不要求整个仓库符合 Atlas 格式。建议个人数据仓库保持私有，可与 plans、health 等个人 Skill 共用。

首次使用按 [onboarding.md](onboarding.md) 检查授权和目标目录，实际初始化发布与回读成功后再开始访谈：

- `atlas/` 不存在或为空：在用户授权内创建资料库。已有提交使用当前仓库 HEAD；无任何提交时 snapshot=null，并由宿主工具完成首个提交。
- `atlas/` 是有效资料库：校验并复用 vault ID，不重新初始化。
- 仓库根目录的 `atlas` 是文件，或 `atlas/` 非空且不是有效 Atlas：报告冲突，不覆盖、清空或另选隐含目录。
- 读取失败、权限不足、清单截断：不视为目录缺失，不尝试初始化。

```text
仓库根目录/
├── README.md                  # 可有任意现有文件
├── atlas/
│   ├── vault.json
│   ├── records/               # Markdown 记录
│   ├── sources/               # 原始资料
│   ├── operations/            # 操作与去重记录
│   ├── graph/                 # JSON 图目录
│   ├── manifests/             # 完整性清单
│   └── skill/personal-atlas/  # 可选的静态 Skill 归档
├── plans/                     # 其他 Skill 自主管理
└── health/
```

所有校验、reindex、归档、来源覆盖和删除计算仅覆盖 `atlas/`。不得读取其他目录的个人内容作为 Atlas 证据，不修改根目录 .gitignore、README 或其他 Skill 数据。目录划分不代表连接器具备目录级权限隔离；跨 Skill 查询与写入需额外的明确规则，不能仅因共用仓库自动消费其他目录。

## 路径与提交边界

工具输入与 prepared 输出使用仓库相对路径，例如 `atlas/records/topic/example.md`；图、manifest 和 source.raw_path 等内部引用仍相对 `atlas/`，例如 `records/topic/example.md`。读取内部引用时只加一次 `atlas/`，禁止越界与重复前缀。完整正文链接需指向固定仓库 commit 的实际 `atlas/...` 路径。

计算脚本仅筛选 `atlas/` 子树；允许输入整个仓库快照，但不需要下载其他目录内容。写入前必须确认已经完整列出并读取 `atlas/` 所有文件，防止把缺页当成删除；查询可按需供给相关页面和正文。根目录或其他目录的 vault.json 不参与 Atlas 身份校验。只在用户请求归档时保存静态 Skill 副本到 `atlas/skill/personal-atlas/`，不执行远端副本，不将凭据归档。

宿主发布 prepared 变更时以当前仓库树为基础，仅应用 `atlas/` 路径的新增、修改和明确删除；不能用 Atlas 子树生成一个替换整个仓库的空基树。先核对所有输出路径都在 `atlas/`，再以一次原子提交发布正文、来源、图、清单与操作记录。工具不能保护并发或无法一次提交多文件时，只完成准备和查询，停止写入。

`base_commit` 是整个仓库的提交，不是 Atlas 独有版本。即使另一 Skill 只修改 health/，HEAD 变化后也要重新读取当前 HEAD 与 Atlas 子树，核对后重新生成提案；不能直接替换旧计划的 base_commit，也不能强推。operation_id 和去重记录仅在 atlas/operations/ 内维护。

发布后重新读取远端确认提交与 operation_id；HEAD 已前进时验证候选提交是否在分支历史且内容符合预期，不把任意新 HEAD 当成功。响应丢失先查操作记录，结果不明时报告候选提交，不用新 operation_id 盲目重试。权限、分支保护、限流和网络失败不通过降低安全设置绕过。

## 旧根目录格式

旧版根目录的 vault.json、records/、graph/ 等不会自动加载或迁移。若用户希望继续使用这些资料，先说明新布局并请求明确迁移范围，再在固定快照校验旧数据、核对 atlas/ 无冲突；获准后将该 vault 的全部文件移入 atlas/，保留 vault ID 和内部相对引用，并在同一次受并发保护的提交中完成移动与回读。不得把根目录同名的无关文件一并移动。未授权迁移时保留原状；新建 atlas/ 也不等于旧资料已迁移。

普通删除不清除 Git 历史；彻底忘记的范围见 mutations.md。平台和工具的文件大小、首个提交等能力依实际检查，不声称所有平台均已实测。
