# 原始材料与完整性

## 保存和提取是两步

```text
python3 -B <skill>/scripts/atlas.py ingest --stdin --name input.txt --title "来源标题" --domain life
python3 -B <skill>/scripts/atlas.py source <返回的source_id> --offset 0 --limit 80
```

ingest 从 stdin 在内存接收原始字节、计算哈希、建立 source 节点、生成图并提交到远端；不调用模型做提取。返回 extraction=unprocessed。已存同哈希会返回原 source_id，不重复复制。删除过的来源哈希被标记，不能因重新导入而悄悄复活。

用户口述也要保存为来源：在内存构造准确原话、说话人和本轮可核验的日期/上下文，再经 stdin 传给 ingest。用工具 stdin 或 subprocess.run(..., input=raw_bytes)；不得写入临时文件，也不要使用可能被 shell 落盘的 heredoc。只保存用户授权记忆的相关内容，不把整个会话或机器上的其他文件擅自导入。

## 分批处理

1. 确定来源格式和完整范围（行/消息/页/文件/时间码）；保留原材料不损失细节。
2. source 元数据登记 scope、units；单位按章节、消息批次、日期或自然会话拆分，初始 pending。
3. 每批提取明确事实、事件、关系、偏好等；保留主体、否定、条件、例外和来源定位。对需要相邻上下文的单元连读，避免断章取义。
4. 查重复和实体别名；合并相同事实的证据，不合并不同时间的相似事件。
5. 生成 put 操作，同时更新本批 units 为 processed 并登记 record_ids；失败单元 failed + note，没事实的单元 processed + note。
6. 全部范围核查完且单位确实覆盖 scope 才标 complete；否则 partial。原文未读过的部分不能因“看起来重复”直接算处理完成。

单元很多时可以把原文按自然边界分别 ingest，额外建立一个来源集合的导航节点用 part_of 关联。集合的实际完整范围应明确记录，不让单个 source 元数据无限膨胀。

## 格式处理

- Markdown/TXT：source 按行读；保留标题、段落、时间和人名。
- CSV：通过标准 CSV 解析器读，保留表头和行号；不要直接按逗号拆分。
- JSON：按格式解析，locator 用消息 ID 或 JSON 路径；超长一行不直接回显。
- 聊天：保存说话人、发送时间、顺序、引用及相邻回复；对方的话不能自动记成用户自述。
- PDF/图片/音视频：原文件先保存远端，当前环境支持远端/内存输入的能力负责 OCR/转写/页面读取；识别结果另作来源并通过 derived_from 关联原文件。无法识别部分标 failed 或 pending。
- SQLite/其他二进制：保留原文件，采用格式对应的只读解析；不要凭文件后缀宣称已提取成功。

本 skill 没有捆绑 OCR、音视频识别、聊天数据库解密或第三方账户爬取功能，不能承诺 ingest 自动完成这些工作。

## 大文件与证据

文本记录尽量小，原始二进制不强制转为 Markdown。直接存原始附件，单次 ingest 上限 20 MiB；更大资料在内存中按自然边界拆分。只能通过本地下载才能工作的解析器不适用于当前模式；无法远端或内存处理时标记未处理，不静默创建本地副本。尚未实现 LFS 自动配置、远端对象存储或附件引用适配，不把外链当作已有完整备份。

图仅保留来源摘要、定位和覆盖信息，不复制全文。引用需足以重新找到原句，但无需在每个事实中重复大段原文。

导入结束分别报告：原文件已保存、产生多少条记录、哪些范围提取完成、哪些还没处理、图状态、远端提交确认状态。不要把“覆盖单元已标 processed”说成对未知事实的全量保证。
